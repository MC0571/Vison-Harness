# PR 与合并

## Pull Request

确认工作区无意外修改、分支不是受保护目标、base/head 准确、提交与范围匹配，并查询是否已有等价 PR。推送和创建前重新读远端；结果超时先按 head/branch 查询。PR 正文列实际检查与未执行范围，不把计划写成结果。

## 合并

合并需要单独明确授权。执行前重读当前 head/base、冲突、必需检查、审查与关闭语义；使用平台提供的条件/期望 head 能力。成功后读取实际目标分支提交确认；失败保留原分支，不绕过保护。

若事项要求合并后回读或验证，PR 正文和合并说明使用 `Refs #N` 等普通关联，避免自动关闭。合并完成、目标分支回读和事项关闭分别报告。
