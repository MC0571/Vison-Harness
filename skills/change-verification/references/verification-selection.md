# 从承诺推导检查，而不是从工具清单反推工作

## 选择过程

> 当前要支持的结论 → 违反它的具体错误 → 能观察错误的位置 → 最小判别检查 → 尚未覆盖的部分。

先固定本轮层级：静态设计、构建产出、接口行为、安装加载、发布结果或其他明确承诺。验证设计本身不等于每次都要执行全部层次。

## 判别力

问“假设实现犯了这个具体错误，此检查会不会仍通过”。会通过则换观察点、补独立期望或增加必要的较高层检查，而不是反复运行同一个无效检查。

例：格式正确的包仍可能漏掉运行资源，须检查实际内容；模块测试绿色仍可能遗漏真实调用入口；退出码为零仍可能产生了不被允许的写入。

## 证据层次

| 证据 | 支持什么 | 不单独支持什么 |
| --- | --- | --- |
| 静态审查/格式/结构 | 给定材料的设计、解析、引用或结构判断 | 已执行的运行效果 |
| 单元/局部检查 | 目标责任内的逻辑与边界 | 被替身隔离的集成行为 |
| 集成 | 真实组件间契约与数据流 | 未进入的完整部署或使用路径 |
| 正式构建 | 按项目入口产出指定构件 | 安装后发现与行为 |
| 安装/加载 | 特定环境的可发现、可读取与加载 | 所有宿主或用户任务结果 |
| 行为/使用路径 | 给定输入、环境下的实际结果 | 样本外行为与长期目标 |

低层结果不能平均抵消核心承诺未覆盖。也不能因为有更高层检查可做，就否定已经满足本轮静态范围的结论。

## 变化影响选择

路径解析关注解码、越界、符号链接等本次真实风险；协议变化关注支持调用者、字段与失败语义；迁移关注中断、重试、新旧组合和数据保留；普通文案关注内容和引用；Agent 指令则按其决策影响判断，不能只按 Markdown 扩展名免除思考。

这些是示例，不是无条件检查套餐。性能、并发和长期效果只有进入当前承诺或可信风险时才展开，不填固定覆盖比例、样本量或统一阈值。

## 最小且足够

先复用仍有效的证据，合并能覆盖多个相关失败的检查；对相同前提重复低信息检查不增加必要价值。关键风险只在真实边界可观察时，选择相应集成，不能用更多单元测试替代。

当前缺口若不影响本轮判断，可明确排除；若影响核心结论，则请求最小所需条件或报告 blocked/未覆盖，不将范围偷偷缩小后称全面通过。

## 例子

承诺“检查命令不修改源文件”：仅退出码 0 不足，应在受控范围比较前后内容与相关文件元数据。只在需要证明该只读承诺时做这项检查，不把全树快照加到每次普通验证。

承诺“本次只评静态设计”：直接检查方法、边界、反例与一致性即可，不新增真实 Agent 效果评估作为条件。
