# 证据范围、复用与结论

证据绑定检查对象、准确候选、环境、执行入口、输入和覆盖。代码提交不一定包含未提交变化，文件存在也不证明实际加载；结论只到来源支持的层级。

## 三种方式

- 直接执行：本轮对明确候选运行检查，保留命令、结果和副作用。
- 继承复用：原检查确实执行，当前变化未破坏其结论前提；注明来源和继承理由，不说本轮重新执行。
- 证据审计：检查原始日志、构件与元数据能否支持声明；作者摘要只作导航。

## 判断是否仍适用

先问原证据证明哪条具体结论、依赖哪些代码/配置/环境/输入前提。再看当前变化是否触及它们或相关调用、生成、加载关系。

未受影响且来源明确时复用。改变依赖、入口、权限、生成规则、协议或关键数据条件时，只让对应结论失效并补验。不同 SHA 不自动使所有证据失效；相同 SHA 也不自动保证环境与构件相同。

无法查明影响时说明具体不确定性和最小补验，不笼统继承，也不默认重跑全部。

例：普通文案变化不触及构建前提，可继承先前构建并补内容检查；修改 Agent 指令虽然也是 Markdown，却可能改变工作行为。应根据本轮所需结论分析，不按后缀决定。

## 结果语义

pass 表示相应检查执行并满足判据，若为继承须同时明确原运行；fail 表示执行后违反判据；blocked 表示所需环境/权限阻止检查；not-run 表示未执行；not-applicable 表示该检查与本轮承诺确实无关。

被阻塞的必需检查不能改为不适用；设置失败不能冒充目标行为红灯；继承结论不能冒充新运行。保存首次失败与重试原因，不用重复运行冲淡失败。

## 层级与成本

静态设计、格式、单元、集成、构建、安装和真实使用路径支持不同结论。大量低层通过不能抵消核心缺口；没有更高层运行也不自动否定一个明确限定为静态的审查。

验证针对当前承诺与可信风险，具备条件就结束，不追求检查数量。自检、独立审查、用户验收、提交、合并与发布授权仍分别判断。

原始输出应脱敏；既保留足够可核对信息，也不泄漏令牌、凭据或无关个人数据。结果不明先查询，不盲目重复外部动作。
