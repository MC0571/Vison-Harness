# 关键假设的有界核验

只对会改变当前路线、范围或重要技术选择的未知使用本方法。

1. 先写明哪个具体决定依赖该假设，以及假设为假时会改变什么。普通适配成本或远期好奇不构成关键假设。
2. 查找对象、版本、环境和范围仍适用的现有证据；能直接复用时说明适用理由，不重复试验。
3. 证据不足且结果会改变路线时，设计最小调查。执行前固定观察量、环境、有限时间/样本预算、停止条件，以及支持、否定和仍不确定的判据。
4. 执行后分开记录直接观察、基于观察的推断和仍未知内容。环境、权限或工具失败只说明本次调查受阻，不等于产品路线不可行。
5. 只阻塞依赖该假设的决定；不受影响的规划、文档或实现继续。

例：方案依赖“目标 API 支持条件写入”。先查当前 API 版本的官方契约；仍不清楚时，用隔离对象做一次有预算的并发写入试验。若账号无权限，结论是试验受阻，而不是 API 不支持。

异常例：已有半年前的吞吐证据，但候选算法和部署规格未变。可以复用并注明版本；若数据规模已翻倍，只补受影响规模区间，不重跑全部验证。
