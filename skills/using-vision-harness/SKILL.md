# Vision-Harness: Using Vision Harness

交付“现在可接手什么”：目标项目、当前承诺、有效事实入口、允许动作、真正缺口和一项可执行下一步。

## 何时使用／何时不使用

仅在当前任务缺少足以判断目标项目、范围、授权或下一步的上下文时使用；新会话本身不构成缺口。用户已给出明确对象、实施范围和授权时直接进入实施，不要求先走本入口；本技能不替代实施、审查、验证或交付。

## 输入与环境条件

输入至少包含用户请求和可定位的项目线索。可以从当前目录、版本控制、项目文档、工作项和宿主状态读取事实；产品取舍、授权扩大或冲突授权只能由用户决定。某一来源不可用只限制依赖它的结论。

## 开始前的最少读取

1. 确认目标项目与当前工作目录，避免把方法包示例当消费项目事实。
2. 读取本轮请求、适用项目规则和当前分支/候选。
3. 只定位足以回答当前问题的目标入口、工作项、相关约定和最近证据；事实足够时不全仓扫描。

## 执行步骤与关键分支

1. 用一句话固定本轮期望结果和停止位置。
2. 按对象、版本、范围和时间核对来源；分开列出已确认决定、建议、未知、授权和证据。
3. 找到消费项目的当前工作入口。文件与 GitHub 冲突时检查各自负责的事实，不默认最新文字覆盖全部历史。
4. 判断缺口：可查事实自行查；需要产品取舍或扩大副作用时才请用户决定；缺口只阻塞相关动作。
5. 选择下一项具体动作并给出所需输入与完成边界。可建议一个工作入口名称，但即使其他 Skill 未安装也要完整说明任务范围。
6. 只有用户要求持久化时，才写入既有合适载体；不创建 `SESSION_STATE` 或平行状态文件。

## 输出与完成条件

输出包含：目标项目、当前承诺、有效事实入口、允许动作、真正缺口、可执行下一步。信息足够且下一步可直接接手即正常完成；只读请求返回建议；无新增事实时可返回零写入；来源或权限缺失时标明受阻部分，不能宣称后续工作完成。

## 异常与停止边界

不从 Issue 状态、工具权限或 CI 结果推导授权。冲突未解时不覆盖共享事实；不受影响的只读定位继续。到达实施、外部写入、合并或发布边界即按本轮授权停止。

## 简短输入输出示例

正常：输入“继续 #42，允许改代码并开 PR”。输出项目、#42 与当前 head、可修改范围、未授权合并，以及“直接复现并实施”的下一步。

边界：输入已包含明确缺陷、候选与实施授权时，输出“条件已具备，直接实施”，不要求重跑愿景或本入口。
