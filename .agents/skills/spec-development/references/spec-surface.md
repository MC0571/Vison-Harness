# Spec surface 判断

需要更新 Spec 的信号：用户可观察结果变化；持久状态或转换变化；数据/安全不变量变化；公开或跨组件接口变化；权限、失败、重试、取消或兼容保证变化；必须长期保持的性能/一致性保证变化。

通常无需修改：私有重命名、等价重构、格式调整、测试内部整理、一次实施顺序或工作进度。若重构暴露出原 Spec 含糊，可单独提出澄清，但不能把实现现状直接写成承诺。

分支：

- 新行为：在已有语义域增加可判断条款；没有合适域才新建。
- 明确意图：不改变目标，只消除会导致不同实现的歧义。
- 错误规格：以已确认决定为依据修正，并说明兼容影响。
- 内部重构：记录零修改结论及行为保护依据。

例：数据库索引调整不改变行为，无需 Spec；错误码从可重试改为不可重试会影响调用方，需要 Spec。
