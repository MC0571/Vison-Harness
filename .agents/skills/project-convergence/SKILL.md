# Project Convergence

交付具体偏离的事实、影响和有界纠偏，或“无新事实、无需修改”的结论。

## 何时使用／何时不使用

用于阶段性/系统级冲突、重复规则、架构漂移、失效暂缓承载或无依据复杂度。单个代码缺陷通常直接实现；文件数量多不是健康问题，无新事实时不制造治理改动。

## 输入与环境条件

需要回顾对象、新事实和允许修改范围。目标方向改变、删除已确认能力和大范围代码重构需要相应用户决定/授权；本技能可直接完成已授权、明确、低风险的文档或规划纠偏。

## 开始前的最少读取

只读取与新事实相连的愿景、工作图、Spec、架构、规则、实现和证据，固定各自对象/版本。不要全仓枚举文件来代替问题定位。

## 执行步骤与关键分支

1. 写明新事实以及它可能影响的具体承诺。
2. 建立有限对照：目标 → 工作承载 → 行为约定 → 架构 → 实现 → 证据，仅展开相关链路。
3. 分类为目标遗漏、语义冲突、重复规则、架构偏离、失效暂缓承载或无依据复杂度；没有具体偏离则返回无需改动。
4. 追溯原因：来源过期、边界误解、实现偏离、证据失效或推测性流程；不以工件数量判断。
5. 提出最小调整，说明保留的历史/目标和受影响范围。停止实现路线不自动删除原需求，需要替代承载时明确指出。
6. 只诊断时止于建议；获准时完成低风险限定修改并回读。代码重构、产品方向变更和发布分别交接，不自行越权。

## 输出与完成条件

输出问题事实与位置、影响、建议或已执行限定修改、仍有效历史/目标和剩余授权边界。只读诊断、零改动和环境受阻分别报告；部分受阻不能表述为全项目停工。

## 异常与停止边界

不因局部问题重写愿景/架构/全部规则，不以“简化”删除安全、权限和已确认能力。未经授权不改产品方向、代码、发布或其他项目。

## 简短输入输出示例

正常：新 Spec 已替代旧状态名，但架构与两个规则仍引用旧名；获准后只更新这些引用并保留旧决定历史。

边界：没有新事实且现有入口一致，输出“无需修改”，不创建收敛计划。
