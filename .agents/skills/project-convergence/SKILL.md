# 项目整体回顾与纠偏

读取[共同规则](../../../METHOD.md)。确认触发回顾的问题、时间范围、相关工作及权限；本 Skill 由任务触发，不是后台监控。普通小修改无需全仓审计。

## 重建足够的整体位置

从权威愿景、当前规划、相关 Spec/架构、实际交付和有效决定读取事实。沿本次问题追踪，不要求每次阅读全部历史。区别计划中的能力、已有实现、真实交付、被停止路线和仍未证明的效果。

## 找到偏离的原因

检查确认目标是否遗漏或被当前实现偷换；子项全部完成后上层结果是否仍缺入口或集成；架构边界、规格语义和当前代码是否冲突；暂缓承诺是否有承担位置；旧依赖、重复规则或无必要检查是否增加负担。

从事实构建原因与影响，不把文档数量、提交数量或测试数量当作项目成功。若只有单轮受控记录，结论限于该范围，不能冒充长期效果。

## 给出有界的纠偏

逐项区别继续、局部调整、冻结、替代或停止，并给出证据与条件。停止一条路线不取消它仍有效的用户目标；保留重要决定历史，不复活已被明确否定的路径。

先诊断再选择协作：目标取舍交给 Vision，整体规划交给 Breakdown，单项范围交给 issue-shaping，推进与集成交给 delivery-coordination，结构或流程负担交给设计/简化，规则维护交给对应入口。不是每次全部调用。

只阻塞依赖失效前提的部分，无关工作继续。已有安排合理或没有新事实时明确保持现状，不为了显示回顾价值新建文件或任务。

## 在授权内落实并结束

获准调整时重读目标对象，保留无关内容，更新并回读实际结果；未授权时仅交付建议。回顾权限不授予全仓改写、删除需求、合并或发布。

返回问题、依据、影响范围、已执行调整或零写入结论，以及有效目标的承接位置。区分一次诊断完成、实际纠偏完成和长期效果成立，不把它们压成同一个通过状态。
