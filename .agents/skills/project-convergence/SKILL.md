# Project Convergence

用于系统级 convergence、阶段回顾、重复/失效规则、架构侵蚀、Spec 冲突、Issue graph 偏离、Deferred 失真或 Vision gap。普通局部修改不需要先跑本入口。

## 执行骨架

1. 固定触发问题、时间/版本范围、相关工作和允许动作。
2. 按[Convergence 方法](../../../METHOD.md#11-根据新事实继续调整或停止)恢复足够的愿景、规划、Spec/架构、实际交付和有效决定；不默认全仓扫描。
3. 区分局部实施问题、工作图问题、长期结构问题、规则问题和目标问题；只阻塞依赖失效前提的部分。
4. 工作图/Deferred/依赖问题按需读取[规划与协调方法](../../../METHOD.md#3-保留完整目标但明确本次交付)；Spec/架构冲突读取[Spec 与技术设计方法](../../../METHOD.md#7-按变化维护-spec架构和决策)；Agent/审查配置问题读取[Agent 配置方法](../../../METHOD.md#6-维护-agent-工作约定和审查规则)。
5. 给出继续、局部调整、冻结、替代或停止的有界建议；停止路线不自动取消仍有效目标。
6. 只在授权内落实相应对象，并回读实际结果。已有安排合理或没有新事实时，零修改结束。

共享授权、安全事实写入与治理比例见[共享规则](../../../METHOD.md#1-先确认本轮任务和授权)。一次诊断完成、纠偏完成与长期效果成立必须分开。
