# Vision-Harhess: Project Convergence

判断当前阶段或能力是否仍向有效目标收敛，交付具体偏离、影响和限定纠偏；没有实质偏离可零修改。

## 两种并列模式

- 事件纠偏：已有新事实、冲突或失效迹象，从受影响链路定位。
- 阶段检查：用户要求回顾某阶段、能力或整合结果，从该范围的有效承诺主动寻找遗漏与交互问题，不要求用户先指出缺陷。

单个明确代码 bug 通常直接实施；文件多或风格不同本身不是系统偏离。没有检查请求、新事实或相关变化时不主动制造全仓整改。

## 输入与开始前的最少读取

固定回顾对象、承诺层级、准确候选和允许动作。事件模式从事实扩展相关链路；阶段模式读取该阶段目标、工作承载、行为/架构、实际实现与适用证据，不默认扫描全部历史或所有未来能力。

## 工作方法

1. 确定模式与边界，区分当前阶段、长期能力、Deferred、Non-goals、旧决定和未知。
2. 建立有限意图清单及“目标 → 工作承载 → 行为约定 → 架构/实现 → 证据”对应，缺某类文件不自动是缺能力。
3. 正向查确认承诺的缺失、部分实现或矛盾；反向查实现/规则/工作是否有依据。Issue 已关闭、代码存在、测试绿色都不单独证明系统收敛。
4. 检查真实跨组件路径、共享状态、错误传播、权限和版本交互，寻找多个局部正确仍无法整合的地方。
5. 对疑点比较对象、范围、版本与实际保护，过滤合理差异、已取消方向和无关旧问题。证据不足与已证实实现偏离分开。
6. 按根因与影响选择最小纠偏，明确应修改哪个权威事实或实现、哪些历史与目标保留；停止一条路线不自动删除原需求。
7. 只诊断则给建议；已授权且风险明确的限定文档/规划修订可完成并回读。代码重构、产品方向、合并或发布分别按权限处理。

## 输出与完成条件

给出检查范围/候选、具体事实与影响、建议或实际修订、未覆盖部分和剩余权限。当前检查范围的适用承诺及重要交互已有明确判断即可，不以发现数量或全仓覆盖为目标。未发现偏离可正常完成，但不能将没读到的范围称作一致。

## 停止与例外

无关远期未知不阻塞当前工作；局部问题不触发全项目重写。文件没有更新不证明语义错误，文档是 Markdown 也不自动说明修改低风险。未经授权不缩小目标、删除安全规则或改变代码。

## 示例

阶段各子项均关闭，但正式调用路径没有连接持久化：报告当前阶段结果缺失及对应责任，不因子项状态齐全判断收敛。没有新已知缺陷但用户明确要求阶段检查时，应完成有界对照，不以“无新事实”拒绝调查。
