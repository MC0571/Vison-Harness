# 代码审查

读取[共同规则](../../../METHOD.md)与[审查规则](../../../METHOD.md#9-按对象组织审查而不是机械增加审查轮次)。确认仓库、base/head、相关承诺、项目规则及本轮是否只读，不能把旧提交的审查结论套到新候选。

## 读取真正受影响的路径

从 diff 找到变更入口，读取必要上下文、直接调用者、状态或数据所有者及相关测试。对生成文件检查来源；对依赖或配置变化检查实际生效路径。避免全仓漫游，也不能只看新增行忽略周边语义。

## 检查正确性而非个人偏好

沿真实输入追踪到返回、持久化和外部副作用，寻找与 Spec 或本轮承诺不一致的路径。重点检查适用的权限、输入校验、错误传播、资源生命周期、状态转换、并发、重试、取消和兼容边界。

判断是否破坏模块边界、依赖方向或数据归属；新增抽象、防御和兼容路径是否有依据。必要保护不能因为代码显得冗长而删除，内部命名差异不应冒充功能缺陷。

检查测试是否断言用户可观察结果、是否能在错误实现下失败，是否遗漏持久化、调用整合或负例。现有测试通过只证明已覆盖范围。允许实际运行时使用仓库真实命令；不能运行则明确基于静态检查。

## 对发现建立因果链

每个问题给出精确位置、可发生的条件、错误结果、相应依据及最小修正方向。区分新增回归与既有问题；不相关旧问题不自动阻断本次。去掉重复、无法证实及纯风格意见。

独立审查须直接取证并自行判断；同一实施者复查只能称自检。缺失上下文导致结论受限时说明，不猜测代码安全或已通过。

返回准确候选、实质发现或未发现阻断、执行过的检查和未检查部分。发现问题不自动修复；获准记录时写入对应 PR。修订后聚焦受影响路径重看，不要求无关检查全部从头执行。
