# 变更设计

1. 固定已确认行为、现有约束和不能破坏的不变量。
2. 描述受影响组件、真实调用/数据流及责任边界。
3. 只比较能满足约束的方案；对每项说明复杂度、失败模式、迁移和维护代价。一个方案明显成立时直接选择。
4. 给出实施顺序：先稳定契约还是先迁移数据，哪些步骤可并行，何时切换。
5. 说明兼容窗口、数据迁移、失败回滚、观测信号和验证入口。
6. 将一次方案写入用户授权的现有 Issue/PR；除非决定长期影响多个后续工作，否则不新建 ADR。

例：字段改名有现存外部调用方时，可选择读双格式、写新格式的有限迁移窗口；明确删除旧读路径的条件，不保留永久双写。

异常：唯一方案依赖未知平台上限。先做最小调查；若权限阻塞，保留两个受影响分支，不把整项设计标成产品失败。
