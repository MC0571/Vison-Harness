# TDD 实施与缺陷处理

读取[共同规则](../../../METHOD.md)，从请求、Issue、适用指引与 Spec 确定本轮承诺、允许修改范围和停止位置。检查当前分支与未提交改动，保留用户已有工作；命令来自实际配置，不猜测测试入口。

## 选择当前路径

明确缺陷先复现实际错误，记录输入、预期、实际结果和对应版本，追踪最早偏离约定的位置。只授权诊断时，交付原因及证据后结束。需要产品决定的歧义只暂停相关修改，不重新访谈整个项目。

新行为按可观察结果划分切片，覆盖整个本轮承诺；纯重构先确认现有行为保护。已有足够 Spec 和架构时直接使用，不为实现再生成一套文档。改变长期行为或结构时，将必要问题交给相应规格或设计工作。

## 对每个切片执行红、绿、重构

先添加针对目标行为或缺陷的测试，并实际运行确认失败原因。环境、依赖或测试语法错误不是有效红灯。不能通过先写实现再倒填“之前失败”伪造顺序。

只实现使当前行为正确的必要修改，执行目标测试确认变绿。保留权限、输入、数据完整性和错误处理保护，不将异常吞成默认成功。重构重复和不清晰结构，再运行受影响检查；不提前实现不在本轮范围内的未来能力。

遇到现有失败时区分基线问题和本次回归。没有运行环境时仍可在授权内实现及准备测试，但必须明确哪些测试未执行，不能宣布红绿闭环或用模拟结果冒充真实通过。

## 完成本轮而不是仅完成测试

沿本轮承诺检查正式入口、状态持久化、调用者、兼容和必要整合是否遗漏。只重跑受影响检查；需要更广证据时交给 change-verification。文件存在和测试全绿均不能自动证明全部承诺成立。

按项目规则交付准确 diff、候选提交、运行结果、失败和未验证范围；必要时由 code-review 直接审查候选。审查指出真实问题再修复，不因风格偏好反复扩大实现。

在授权内创建分支、提交或 PR；没有相应授权就停在本地修改。不得覆盖用户未提交内容、强推共享分支、自行合并、发布或关闭长期能力。需要新会话继续时，将必要事实留在已有工作记录，而不是私有状态文件。
