# TDD Development

交付获准范围内的实现与测试，或在只授权诊断时交付原因和证据后停止。

## 执行骨架

1. 从请求、Issue、适用指引与 Spec 确认本轮承诺、允许修改范围、当前分支/候选和停止边界。
2. 缺陷先复现并追踪最早偏离；只授权调查时不要修复。新行为按可观察结果切片，纯重构先确认现有行为保护。
3. 按[实施与复杂度方法](../../../METHOD.md#8-用-tdd-实施同时抑制没有依据的复杂度)执行红灯 → 绿灯 → 重构。红灯必须是目标行为失败，不是环境或测试语法错误。
4. 只实现当前行为所需内容；权限、输入、数据完整性和错误保护不能以“简化”为由删除。推测性未来抽象、兼容路径或治理步骤没有依据时应去掉。
5. 遇到真实语义歧义或长期架构变化，只暂停受影响部分并返回相应 Spec/技术设计；无关实施继续。
6. 结束前沿本轮承诺检查正式入口、持久化、调用者、兼容和必要整合。需要更广证据时读取[证据与验证方法](../../../METHOD.md#10-用适用证据判断完成和交付)或直接交给 change-verification。

授权、安全写入和条件充分时继续的规则见[共享规则](../../../METHOD.md#1-先确认本轮任务和授权)。

测试全绿不等于全部承诺已证明；当前切片完成也不等于长期能力完成。没有合并/发布授权时停在相应边界。
