# 调试：建立能区分原因的反馈

## 固定原始症状

记录准确候选、输入、环境、预期和实际结果。先确认调查的是用户报告的错误，而非附近另一项失败。日志、请求和输出中的令牌、个人信息与凭据先脱敏；不要为方便复现扩散真实数据。

## 选择最小反馈方式

| 当前条件 | 可用方式 | 判别重点 |
| --- | --- | --- |
| 已有失败测试 | 运行目标测试 | 它是否针对本次症状 |
| 请求或 CLI 可复现 | 隔离 HTTP/CLI 调用与固定输入 | 断言确切错误，不仅断言退出正常 |
| 线上事件难复现 | 获准取得并脱敏后重放请求/事件 | 保留造成失败的必要时序和数据 |
| 新旧版本不同 | 相同输入差分、定位变化区间 | 排除环境与配置差异 |
| 变化区间明确 | 用稳定反馈二分代码/数据版本 | 反馈是否对每个候选有效 |
| 输入空间难穷举 | 有限预算的性质/随机检查 | 期望性质必须有契约依据，固定种子 |
| UI 交互问题 | 可用浏览器自动化或受控人工步骤 | 观察真实路径、状态和网络 |
| 性能回归 | 同条件基线、剖析或查询计划 | 区分慢在哪里，避免先优化猜测位置 |

这些是可选方法，不是必须依次执行的清单。优先让反馈更快、更准确、更确定，不设所有项目必须达到的秒数。

## 缩小复现

一次删减输入、调用、配置或时序中的一个因素，每步重跑以确认仍是同一故障。保留原始复现，修复后还要回到原场景。缩减到足够区分原因就停止，不为得到数学意义上的最小输入无限投入。

## 假设与探针

从观察提出少量可证伪原因，每项说明“若原因成立，会观察到什么变化”。存在合理竞争解释时不要只追第一个故事；原因已明确时也不强凑三到五个假设。

选择最能区分解释、成本和副作用最小的检查，一次改变一个因素。优先断点、目标状态检查或边界日志，不无差别记录全部数据。临时日志使用可定位标记，并在收口时移除。

## 偶发与不可复现

在隔离且获准环境固定种子、时钟、并发窗口与外部响应，设置有限样本预算，报告失败频率。加压可能影响共享资源，不能未经授权在生产上尝试。

无法运行复现时仍可分析代码、日志和配置，并提出带依据的假设与下一判别动作；不能宣布根因已证实。缺访问权限只限制依赖该环境的结论。连续尝试无信息增益时改变反馈方式或说明真正所缺条件，而非随机修补。

## 修复与清理

在实际拥有该行为的最小正确位置修复。已有稳定失败检查可复用；否则将复现转为能抓住真实故障模式的回归。若可用测试边界无法表达多调用者交互，改选集成边界，不以浅层绿色冒充保护。

修复后运行回归与原始场景，按影响检查其他调用者；清除本轮诊断残留并保留有用复现，不能删除用户原文件。只诊断请求不修改候选，返回观察、排除项、未证实假设和最有价值的下一检查。
