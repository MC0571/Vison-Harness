# PR 推进条件审查

读取[共同规则](../../../METHOD.md)与[审查规则](../../../METHOD.md#9-按对象组织审查而不是机械增加审查轮次)。取得真实 PR 的目标分支、当前 head、diff、关联工作、审查和 Checks；不能只凭标题或作者完成摘要给结论。

## 核对当前承诺

比较本次 diff 与有效范围，识别缺失、无关扩张、未说明的行为或架构变化。检查用户能通过本次承诺的入口取得什么，不用底层文件齐全冒充交付。

## 判断已有证据是否适用

把必要审查和测试结果对应到准确候选、环境及覆盖。旧 head 的审查不是自动无效，也不是自动继承；读取后续变化，说明未受影响的依据及需要补看的部分。

检查失败、跳过、取消和未运行项，不将没有 Checks 当作绿色。规格审查、代码审查、验证与负责人接受分别表达。只在缺口影响当前判断时请求对应工作，不再机械跑一套固定流水线。

## 区分技术可推进与操作获准

读取项目实际合并要求和本轮授权。证据足够但未授权合并时，可判断技术条件满足并停下；工具有写权限不构成操作授权。作者自检不是独立审查；缺少项目要求的独立判断时准确列明。

检查关闭语义：有合并后回读或验证条件的工作使用普通关联，不借自动关闭关键词提前宣告完成。没有此类条件的 PR 不受一刀切禁令。发布、合并和关闭长期能力须各自有依据。

## 返回当前可执行结论

明确候选、满足项、真实阻断、非阻断建议、未证明部分和下一步。结论可以是可在授权内推进、仅缺操作许可、需要处理具体问题，或资料不足；不要把所有未知都当阻断。

最终判断前重新读取 head；若改变，按差异更新结论。只在授权内记录审查，不自动修复、合并、关闭或发布。
