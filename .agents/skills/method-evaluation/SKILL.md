# Vision-Harhess: Method Evaluation

这是研发仓库维护者入口，不装配进普通 Plugin。以行为 Spec、架构职责矩阵和公开/盲测场景作为独立依据；Skill 自己不能成为唯一成功标准。

## 选择本次评估层次

区分结构与断链、入口路由、条件 reference 加载、单入口行为、跨入口协作、正式包安装与长期效果。只验证受当前变化影响的层次，旧证据只有在候选、环境和覆盖未受影响时才能复用。

入口合并后，重点读取 evals/work-entry-routing：既检查自然请求是否到达正确工作入口，也检查横切方法只在触发条件出现时使用；不能把“加载更多治理”当作更高质量。

## 隔离候选与判断

候选只获得实际分发材料和当轮项目输入；Spec、oracle、评估者笔记、未来轮次与未见案例保持隔离。多轮按顺序释放，新会话不携带旧 transcript 或隐藏摘要。

正反成对覆盖：该停时停、授权充分时继续；关键未知时验证、无关未知时不阻塞；旧证据失效时补验、仍适用时复用；需要项目局部规则时配置、无差异时零写入。

## 记录与结论

只有真实运行才记录为运行证据；模拟、静态检查和宿主安装分别限定结论。保留失败与重试原因，记录候选、宿主/模型、输入、输出、副作用和可访问原始产物。

严重越权、确认目标遗漏、错误修改共享事实或错误阻塞充分任务不能被其他成功平均抵消。作者自检、独立评估和接受分别报告；评估完成不自动授权合并或发布。
