# 维护者方法评估

这是研发仓库的维护者入口，不装配进普通用户 Plugin。读取根目录 METHOD.md、ARCHITECTURE.md 以及本次相关行为 Spec；采用独立于当前 Skill 实现的判断依据。用户要求直接交付且未要求扩展评估时，不主动把 Eval 设为开工前置。

## 确定本次要回答的问题

先确认候选、范围、允许环境与有限预算。区分结构检查、工具测试、宿主发现、单入口行为、组合路径和长期效果，只选择影响当前判断的层次。旧证据能适用时说明依据并复用，不无条件重跑。

## 准备隔离的输入与判断

沿已有规格选择代表性正反场景，既检查该停时停，也检查条件充分时继续、无变化零写入和不必要治理。不得从实现输出倒推 oracle，也不把固定措辞或唯一 Issue 树当正确答案。

候选只获得实际分发的运行材料和当轮项目输入；未见案例、判据、开发 Spec 与评估者笔记留在执行空间之外。多轮输入按顺序释放；新会话不得带旧 transcript 或隐藏摘要。

## 执行与记录

只有获得运行授权且具备真实宿主时才执行，记录候选、宿主/模型/工具、输入、输出和副作用。用允许的隔离项目，不访问未授权外部资源。保留失败、重试原因和未执行项；文字推理或模拟不算真实写入。

将原始产物保存在获准的可读取位置，并给出清单与校验值。观察目标遗漏、越权、重复写入、无关阻塞、用户纠偏、返工和成本；需要比较时保持任务与环境可比，不捏造改善百分比。

## 形成有范围的结论

逐项对照依据，严重越权、事实破坏或确认目标遗漏不能被平均分抵消。作者自检、独立评估和接受分别报告；没有独立 reviewer 就不能换个角色自称独立。

达到预算或问题已回答就结束，明确支持的结论、未证明部分和受影响的实现建议。评估完成不等于合并、发布或关闭授权，不为补齐报告而扩展到全部长期能力。
