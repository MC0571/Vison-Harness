# Review

这是统一审查入口。先固定对象为 Spec、Code 或 PR，再按对象读取对应候选与依据；不要求三类审查依次执行。

## 必须直接可见的边界

用户只授权审查时，不自动修改被审查对象。工具可写、问题明显、CI 绿色都不会产生修复、合并或发布授权。若用户明确同时授权修复，先形成对原候选的审查判断，再由实施入口处理获准修改。

审查行为约束见[Review 行为约定](../../../specs/review/spec.md)，详细检查方式按需读取[Review 方法](../../../METHOD.md#9-按对象组织审查而不是机械增加审查轮次)。

## 执行骨架

1. 固定仓库/对象、准确版本或 base/head、当前承诺、项目规则和审查权限。
2. 直接读取候选及必要上下文，不用作者摘要代替取证；材料不足时限制结论。
3. Spec：检查行为、边界、失败、冲突、可验证性和承诺漂移。
4. Code：检查正确性、契约、结构、保护、复杂度和测试；不把风格偏好冒充缺陷。
5. PR：核对当前 head、范围、已有审查/证据的适用性与实际推进授权；不机械重跑全部前序工作。
6. 每个问题给出位置/对象、触发条件、依据、影响和最小修正方向；阻断、建议和未检查范围分开。
7. 候选变化后只重审受影响部分。涉及证据复用/失效时按需读取[证据与验证方法](../../../METHOD.md#10-用适用证据判断完成和交付)。

授权和治理比例见[共享规则](../../../METHOD.md#1-先确认本轮任务和授权)。没有发现阻断可以是正常结果。
