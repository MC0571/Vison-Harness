# 整理单项工作而不复制规格

直接读取原工作项、关联决定和必要行为依据，不重新规划整个产品。

## 整理过程

1. 原因：它承接哪项确认目标、缺陷或必要前置？引用原依据，不重写整段愿景。
2. 当前范围：完成哪个可观察结果或内部交接？与上层能力的关系是什么？
3. 边界：明确不在本轮的内容，并区分已确认 Deferred、Non-goal 和未知。
4. 输入：准确候选、需要的契约、环境和依赖结果；依赖注明开始/集成/验收/发布中的哪一步。
5. 关闭条件：对应 Spec 已落实、必要检查覆盖、真实交接已发生、已知缺口有合适承载等。长期行为精确定义仍留在 Spec。
6. 未决问题：只保留改变范围或方案且当前无法查明的事项；可查事实自行查。

## 粒度判断

能够由一个责任方理解并接手、完成后可判断交接结果，就不必再拆。多个不同决定、修改冲突或独立交付边界才可能值得拆分；不把每个编码步骤变成子 Issue。

## 对照

差：“实现完整超时支持，后面再优化。”

好：“本项实现既有超时规格的状态持久化；输入是已确认终态语义与当前存储接口；完成需证明重新读取/重启后状态仍为终态，且迟到结果不能覆盖。通知能力由已有后续事项承载。”具体行为引用规格，Issue 只限定工作与关闭依据。

已有缺陷项包含复现、范围和回归入口时，可只补真正缺口或零修改。标题不完美不是复制新 Issue 的理由。

## 写入与结束

获准则原位最小整理并回读；只建议就交付建议。不要把 Spec 接受、PR 合并和上层目标完成压成一个关闭条件，也不自行扩大授权。
