# Breakdown

按用户直接选择的模式交付：可接手的产品规划、整理后的单项工作，或已授权执行协调形成的统一候选。

## 何时使用／何时不使用

三种并列模式：全景/滚动规划、单项整理、交付协调。不得强制依次执行。明确的单项实现不要求先做全景规划；只要方案的协调不启动实施。

## 输入与环境条件

需要已确认目标或既有工作项、当前请求粒度和允许副作用。项目事实可从愿景、GitHub、Spec、架构、代码和证据读取；产品优先级与未决取舍由用户决定。执行协调还需要真实宿主工具和实施授权。

## 开始前的最少读取

全景/滚动模式读取确认目标和现有工作图；单项模式只读目标 Issue、直接依据与相关边界；协调模式读取参与工作的准确候选、依赖、共享接口、工作树状态和集成入口。不要为单项请求展开全部历史。

## 执行步骤与关键分支

1. 固定模式、结果粒度、允许写入和停止位置。
2. 全景规划：建立目标 → 阶段结果 → 真实产品组成 → 主要工作承载的映射；近期细化到可接手，远期确认能力保留粗粒度，未知不补成需求。
3. 滚动细化：读取已有工作图和当前批次结果；保留有效节点、合并等价工作、解除已满足依赖，只为下一批增加必要细节。
4. 单项整理：直接复用原 Issue，整理原因、当前范围、边界、输入、完成条件和真正未决问题；不升级为全景规划。
5. 协调方案：区分阻塞开始/集成/验收/发布的依赖，识别共享修改，给出串并行、交接条件与集成责任，不启动实施。
6. 协调执行：确认共同输入版本、输出和修改边界；保护工作树并用宿主已有委派或串行执行；核对真实 diff、构件和测试；接口变化时局部调整；把结果整合到同一候选并执行必要受影响验证。只有统一候选与本轮证据成立才完成。
7. 记录 Deferred 与 Non-goal 的区别，优先复用已有工作项，不为每个细节新建 Issue。

## 输出与完成条件

规划输出目标/组件覆盖、阶段结果、近期工作、依赖、未知和下一步；单项输出原因、范围、边界、输入、完成条件和未决项；方案协调输出串并行及交接；执行协调输出统一候选、真实修改和验证。只读建议、零修改与环境受阻分别报告。

## 异常与停止边界

工具/权限缺失只阻塞对应执行，不假装完成。方案模式不写代码；未经授权不改 GitHub、合并或发布。其他 Skill 可替换某一步方法，但缺少它们不能让本技能放弃已承诺的执行协调。

## 简短输入输出示例

正常：输入“三项工作如何并行并落到一个候选，允许执行”。输出共享接口、各自边界，实际集成 diff 和统一候选测试结果。

边界：输入“整理 #18，只给建议”。只返回 #18 的范围与完成条件，不重建产品规划或修改 Issue。
