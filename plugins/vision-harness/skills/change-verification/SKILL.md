# 变更验证

读取[共同规则](../../references/shared-rules.md)。确认待证明的承诺、准确候选、环境、允许执行的命令与副作用。验证不是独立审查，也不能自行改变产品完成标准。

## 从问题选择证据

逐项找出本轮需要证明的关键结果及现有证据，按变化检查适用性。优先运行能发现本次风险的最小集合，未受影响的有效结果可以有依据地复用；不要为了报告完整重跑所有历史测试。

区分文件结构、确定性工具、实际加载、用户路径和长期效果。检查包能构建不能证明宿主调用；单元测试不能代替真实集成；长期用户收益也不是每个普通变更的放行门槛。

## 执行或审计

命令来自项目实际配置和已确认入口。需要数据库、网络、生产资源或外部写入时先确认具体权限；优先使用授权的隔离环境与非敏感数据，不自动提高权限绕过失败。

实际执行时记录候选、命令、退出码、关键输出和副作用。失败先区分产品、环境、权限和测试问题；保留失败，不只留下最后一次成功。结果不明先查询实际状态，不盲目重复外部操作。

审计现有证据时直接读取原始结果与元数据。只有来源、版本、环境和覆盖适用时才复用，说明依据；只有作者口头声明时称为声明而非已核验事实。

## 对照承诺结束

分别报告通过、失败、阻塞、未运行及不适用。静态检查、模拟或手工观察只支持相应结论；没有环境时返回明确限制和可执行命令，不虚构运行。

若关键行为缺少证据，指出具体缺口；若已足够则停止扩展检查。需要修复时交回实施，重要独立判断交给审查；验证本身不授权改代码、合并、发布或关闭。

获准保存时将结果绑定到对应工作或 PR，并确保他人能读取必要证据；不以执行者私有路径替代可访问产物，不建立自己的验证状态数据库。
