# Change Verification

交付能够支持当前判断的证据及明确未证明范围；验证不是独立审查，也不自行改变完成标准或产生发布授权。

## 执行骨架

1. 固定待证明承诺、准确候选、环境、允许命令和副作用。
2. 按[证据与验证方法](../../references/evidence-methods.md#10-用适用证据判断完成和交付)把承诺映射到必要证据。优先运行能发现本次风险的最小集合。
3. 已有证据只有在对象、版本、环境、入口和覆盖仍适用时才复用，并说明依据；受影响部分才重验。
4. 命令来自项目真实配置。外部网络、数据库、生产资源或真实账号需要相应授权；失败要区分产品、环境、权限和测试问题。
5. 直接执行时记录命令、退出码、关键输出和副作用；审计时读取原始结果与元数据。作者口头声明不是已核验证据。
6. 分别报告通过、失败、阻塞、未运行和不适用；证据足够时停止，不为了“更完整”无限扩大检查。

授权、安全外部操作与治理停止条件见[共享规则](../../references/shared-rules.md#1-先确认本轮任务和授权)。

需要修复交回 tdd-development，需要独立判断交给 review。验证本身不修改代码、不合并、不发布、不关闭长期能力。
