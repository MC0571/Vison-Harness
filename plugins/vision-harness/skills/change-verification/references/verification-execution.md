# 执行与记录证据

## 执行前

确认候选身份：commit/head、工作区未提交变化或构件摘要。只记录提交而漏掉实际脏工作区，不能证明检查对象准确。

从真实 manifest、脚本、Makefile、CI 或维护说明定位命令及运行目录。辨认是否写文件、调用外网、连接数据库、使用凭据或触及生产；按本轮权限决定，不因“测试”二字假定无副作用。

检查已有构件先保存其身份，不先重建覆盖后声称原构件通过。已有充分授权的普通检查可连续执行，不逐条重新确认。

## 执行与失败分类

保留退出码、关键 stdout/stderr、生成对象和必要环境信息，脱敏秘密与个人数据。仅保存摘要不足以判断重要失败时保留可访问原始材料，但不额外建设项目状态数据库。

- 产品失败：执行到目标路径并违反明确判据。
- 测试设置失败：夹具、脚本或配置错误使检查不能正确判别。
- 环境/权限阻塞：检查无法在所需条件下执行。
- 结果不明：外部动作可能已发生，需先查询实际状态。

修复设置后可重试并保留前次结果；不得随机重跑到绿为止。修产品代码不属于本技能默认权限，应明确交回实施。

## 回读与候选变化

必要时检查构件或远端实际结果，而非仅接受命令声称成功。检查后候选变化，分析触及哪些证据前提；未受影响结果可保留，其余补验。

复用证据要注明原候选、来源和适用理由；不能把继承写成刚执行。只读审计止于证据判断，除非本轮另外允许取证。

## 结束报告

按本轮承诺列检查方式、候选、结果与未覆盖部分。失败、blocked 和 not-run 都可以是如实完成验证任务的结果，但不能支持产品已经通过。不存在相应要求才用 not-applicable，不能将被阻塞的必需检查改成不适用。
