# 审查规则与入口配置

读取[共同规则](../../references/shared-rules.md)与[审查规则](../../references/engineering-rules.md#9-按对象组织审查而不是机械增加审查轮次)。确认维护范围、宿主和允许修改的项目级配置；不擅自修改全局权限、信任或远端保护规则。

## 查现有安排而不是重新初始化

读取适用 AGENTS.md、既有审查规范、CI 与实际宿主配置。区分通用审查方法、项目特有规则、执行入口和一次审查结果。已有内容足够且可发现时直接复用，返回无需修改。

沿项目风险确认缺口：规格、代码或 PR 哪类判断缺少依据或入口？是规则未定义、引用失效，还是宿主并未加载？不同问题不能都通过再加一份 Markdown 解决。

## 只维护必要规则

项目规则说明触发条件、输入、检查范围、阻断与建议的区别、允许副作用和结束条件。引用 Plugin 的通用方法，仅记录本项目差异；不复制三套通用清单。

长期架构、接口或安全要求已有权威来源时建立引用，不另写一份可能漂移的规则。根指引只承载全仓共用内容，局部差异留在适用范围；必要指引维护交给 agent-instructions。

不能为了当前 PR 更容易通过而自行削弱已有要求。真实冲突交给有权者决定，保留历史理由。

## 接到真实宿主入口

仅使用已确认的宿主配置格式和发现机制，查实际文档或已有可用配置，不凭目录名猜语法。需要子 Agent 时只写角色边界、工具需要和规则引用；宿主不支持则沿已有显式调用，不构建新调度器。

文件存在、手动可读、宿主实际加载和独立判断分别说明。获准且环境允许时检查实际读取路径；无法运行时明确配置未实测，不将它表述为已生效。一次代码审查结果不写回长期规则。

修改前读完整目标，保留现有有效配置，修改后回读与检查引用。返回实际修改、使用入口、适用范围和限制；配置完成不等于任何 Spec、代码或 PR 已经审查通过。
