# 行为规格写作

1. 定义领域概念和责任所有者，避免用某个类名代替业务概念。
2. 写明前置状态或条件，以及什么事件触发行为。
3. 写出可观察结果、持久状态变化和调用方可依赖的保证。
4. 写不变量：无论正常、重试、取消或恢复都不能违反什么。
5. 写异常与失败：拒绝条件、错误可见性、重试/回滚和兼容边界。
6. 用反例检查：实现是否可能符合字面却违反用户结果？若可以，补足语义而非增加实现步骤。
7. 对照相邻规格的术语、状态机、所有权和兼容约定。

模糊：“任务要可靠超时。”

可判断：“运行超过配置期限时进入 `timed-out`；该状态持久化，并且后到达的成功结果不得把它改为 `completed`。超时通知失败不回滚状态。”

未知：“期限由谁配置”若会影响权限或接口，应保留为待决定；不能默认写死。一次迁移顺序留在当前工作载体，不进入长期 Spec。
