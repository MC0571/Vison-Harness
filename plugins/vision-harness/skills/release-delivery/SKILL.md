# 交付与收尾

读取[共同规则](../../references/shared-rules.md)。先区分请求是打包、交付方案、创建 PR、合并、部署、发布还是关闭工作，并确定仓库、目标分支、候选和每项实际许可。公开仓库中的发布同样需要明确授权。

## 确定交付对象

从有效工作范围和实际构建配置确认交付内容、用户获取入口、支持环境和已知限制。核对需要的许可证、运行依赖和说明；不要把研发夹具、测试答案、凭据或消费项目文件混入包。

通过真实现有命令产生构件，记录对应提交、版本和校验值。版本未确定时沿项目已有规则选择候选标识，不自行占用正式版本或创建远端 tag。没有构建入口时说明缺口，不编造安装命令。

## 核对放行条件而不是扩展流程

将已有审查与检查映射到准确候选；只处理当前放行确需的缺口。质量、接受、工具权限和操作授权分开，不能因为构件生成或 CI 绿色就自动发布。

必要回滚或失败处理来自实际部署方式；不可逆操作应明确且取得相应许可。未经授权不修改用户全局安装、信任配置、生产环境或仓库保护规则。

## 执行允许的动作

只打包时返回构件与使用方法。获准创建 PR 时使用独立分支，保留无关改动。获准合并时重读 head、目标分支和当前条件，优先使用工具支持的预期 SHA 检查，发生变化则重新判断受影响部分。

获准发布时核对目标、版本、构件和可见性，执行后读取实际 release、tag 或部署结果。任何远端写入结果不明先查询，不重复创建。不能用命令已发出代替操作成功。

有合并后条件的工作先回读 main 和必要结果，再在关闭授权内显式关闭；没有相应条件的不额外制造手续。关闭当前切片不关闭长期能力，也不把停止路线说成交付成功。

## 返回可使用的结果

给出实际获取入口、候选/版本、交付范围、已完成动作、保留限制和未执行动作。未获合并或发布授权时，停在已交付的构件或 PR，不等待无关长期验证，也不把未验证能力宣称可靠。
