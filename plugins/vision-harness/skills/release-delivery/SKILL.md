# Release Delivery

先确认用户要求的是打包、创建 PR、合并、部署/发布还是关闭工作，以及每一项实际许可。不同动作不能由前一步自动授权。

## 执行骨架

1. 从有效范围和真实构建配置确定交付对象、正式获取入口、支持环境和限制；不把研发 fixture、评估判据、凭据或消费项目文件混入包。
2. 使用实际存在的构建/交付入口；没有入口就报告，不编造命令。检查旧构件时不要先重建后冒充原构件通过。
3. 按[证据与验证方法](../../references/evidence-methods.md#10-用适用证据判断完成和交付)核对审查与验证是否对应准确候选，只补当前放行真正需要的缺口。
4. 获准创建 PR/合并/发布前重新读取当前 head、目标和条件；远端结果不明先查询，不盲目重复操作。
5. 若工作明确要求合并后回读或验证才算完成，避免自动关闭提前结束；实际合并、回读、验证和关闭分别报告。
6. 返回实际构件/入口、候选或版本、已执行动作、限制与未执行动作。

授权、安全写入和完成层级见[共享规则](../../references/shared-rules.md#1-先确认本轮任务和授权)。切片关闭不自动关闭长期能力；构件生成或 CI 绿色也不自动授权发布。
