# 对准根因的限定纠偏

## 先选择正确的承担位置

| 问题 | 可能承担位置 | 不应做什么 |
| --- | --- | --- |
| 当前行为未实现 | 原工作项和实现 | 改 Spec 让错误变正确 |
| 语义真实含糊或冲突 | 有效产品决定与权威 Spec | 按当前代码偏好定产品 |
| 架构责任发生有效变化 | 当前架构；重大选择必要时 ADR | 把所有实现细节写成架构 |
| 规则重复或引用失效 | 原权威来源与必要导航 | 新增第三份统一状态表 |
| Deferred 承载失效 | 既有或必要工作项 | 静默删除仍有效目标 |
| 路线不可行但目标仍有效 | 替代路线与工作承载 | 因为停止一种方案而关闭原需求 |
| 证据不支持完成声明 | 原声明/证据记录及最小补验 | 把未验证直接判成产品失败 |

## 选择最小可行调整

先按根因归并相关现象，再比较收益、风险与影响。修复最早错误承担处，但不为局部问题重写全景。保留仍成立目标、有效历史与无关实现。

需要改变目标、恢复安全保证或调整高影响规则时明确决定与授权。文档和规划也可能改变 Agent 行为或产品承诺，不因扩展名自动认定低风险。

## 只诊断与授权修改

只诊断：交付位置、机制、影响、推荐承担位置和最小后续动作，不写文件或 tracker。

授权修改：完整读取、复核并发变化、修正权威事实及必要引用并回读。风险明确的限定文档/规划修订可在本技能完成；代码、产品方向、合并与发布按各自范围处理。

兄弟 Skill 不存在时仍说明准确交接输入、结果和权限，不把安装另一个 Skill 当作核心结论。

## 调整后判断

只复查被修改影响的承诺与引用。一个局部纠偏完成不代表整个项目收敛；同时，剩余无关问题不阻塞已充分的本次结果。无必要修改时零写入。

例：两个规则分别复制测试命令，其中一处过期。核对真正的命令来源，在另一处改为准确引用，不创建新的全仓操作手册。
