# 规格审查

读取[共同规则](../../references/shared-rules.md)与[行为、架构与审查规则](../../references/engineering-rules.md#9-按对象组织审查而不是机械增加审查轮次)。固定审查对象、准确提交或版本、当前承诺和允许动作。审查权限不含修改被审查对象。

## 直接读取候选与依据

读取候选全文及其 diff、当前 Issue 的有效范围、相关共享契约和相邻规格。作者摘要只用于导航，不能代替取证；材料被截断或关键依据缺失时，明确检查边界，不给无条件接受。

## 按场景找实际缺口

用主要参与者的成功路径追踪输入、状态和结果；再检查相关失败、权限、重复或迟到输入、并发及兼容边界。只检查当前适用风险，不要求每份规格包含所有技术主题。

区分需求缺失、互相矛盾、不可验证、技术方案冒充需求，以及合法实现自由度。核对当前承诺是否被扩大、缩小或用未知替代。共享概念应与相邻约定一致，未决产品取舍不能被审查者擅自补定。

尝试构造“实现符合字面但违反用户结果”的反例。若可以，指出具体歧义及影响；若差异只是排版或个人偏好，不列为阻断。不按标题或文件数量评分。

## 形成有限判断

每个问题给出位置、触发条件、所违反的依据、影响和最小修正方向；不虚构严重级别，不为了体现工作量凑问题。将阻断、非阻断建议和未检查部分分开。

声明判断是独立读取形成，还是实施者自检；不能仅换角色名称就称独立。没有问题时明确当前范围内未发现阻断，但不宣称实现、安装或发布已完成。

返回候选、结论、问题与检查范围。仅在获准时将审查结果写到既有 PR/Issue；后续候选变化只重新检查受影响部分。必要规格审查发生在依赖它的大量实施之前，不机械拖到编码之后。
