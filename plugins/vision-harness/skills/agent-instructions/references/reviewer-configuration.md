# 审查规则与宿主配置

先区分三类缺口：

- 缺规则：项目没有说明审查对象、发现格式或只读边界；
- 缺引用：规则存在但宿主入口没有指向它；
- 缺执行入口：规则和引用都在，但没有可调用 reviewer/sub-agent 配置。

只补当前缺口。规则明确候选、基线、检查重点、输出严重程度和不得修改候选；配置采用真实宿主当前支持的格式、位置和字段。Markdown 规则不能直接当 TOML 配置，示例配置也不能冒充已加载。Reviewer 数量由实际独立性和风险决定，不预置三名或固定轮次。

从官方资料核对失败时，停止在通用审查规则和待验证字段清单；不猜模型名、工具名或权限字段。修改配置后用宿主发现/读取能力验证，无法运行真实审查时明确“入口存在但结果未验证”。

例：项目已有 code review 规则但配置引用旧路径，只修引用并验证加载；不重写规则或新增 reviewer。
