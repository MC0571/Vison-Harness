# 审查规则、入口和执行配置

## 三种不同缺口

规则缺失：没有说明对象、判断依据、finding 质量或只读边界。

引用缺失：规则已在权威位置，执行入口未指向它。

执行入口缺失：需要真实可调用 reviewer，但宿主配置未建立。

只补本次缺口，不因为有三类概念就生成三份文件或三个 Agent。

## 先写清审查任务

明确候选与基线、要求忠实度和工程质量的适用重点、阻断与建议区分，以及不得未经授权改候选。规范应要求 finding 有位置、条件、机制、影响和依据，也允许无问题结果。

通用方法已有来源时引用；项目特有约束在项目维护。一次审查结论留在对应 PR/Issue，不写回长期规范当进度。

## 再核对宿主机制

从现行官方资料或可信本地配置确认格式、位置、字段、发现与加载方式。不猜模型、工具、权限字段；角色名称不等于实际权限隔离，配置只读也不自动证明运行时权限有效。

按任务风险与真正独立性选择执行方式，不固定两名/三名 reviewer 或多模型。需要独立判断时应直接读取冻结候选与原始依据，不能仅复述作者摘要。

## 修改与验证边界

保留有效权限与审查标准，只改必要配置或引用。回读并使用真实宿主能力检查发现/读取；没有能力时标明限制，不能将示例配置称为已加载。

建立配置不自动授权启动审查、修代码、合并或发布。宿主格式查不到时可完成通用规则和待核对字段说明，不创建猜测配置。

例：审查规则可用但入口引用旧路径，只修引用；无需重写全部规则。没有项目特有差异时直接引用已有方法，不生成冗余审查手册。
