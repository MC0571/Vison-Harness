# Breakdown

交付可接手的产品规划、整理后的单项工作、协调方案，或获准执行形成的统一候选。结果由本次请求决定。

## 何时使用／何时不使用

全景/滚动规划、单项整理、交付协调是并列模式。明确实现不要求先全景规划；协调方案不启动执行；执行协调不能停在静态方案。

## 输入与开始前的最少读取

固定目标或既有工作项、当前粒度、允许写入和停止位置。全景读取目标与已有工作图；单项只读其直接依据；协调读取参与工作的准确候选、共享契约、依赖、工作区状态与集成入口。只补会影响当前取舍的背景。

## 工作方法

1. 固定模式与结果粒度。区分完整目标、当前承诺、已确认的 Deferred、明确 Non-goals 和未确认未知。
2. 全景规划建立“目标结果 → 具体交付组成 → 工作承载 → 阶段完成依据”。双向检查：目标是否遗漏，工作是否缺少目标依据；未知不补成需求。
3. 滚动规划复用有效节点与身份，按新事实局部调整依赖与下一批；粗粒度保留远期能力，不提前拆成文件级任务。
4. 需要拆分时先选择工作性质：待解决的决策、可验证行为切片、内部准备或跨范围迁移。分别使用适合的拆法，不强迫每项工作穿过所有技术层。
5. 单项整理复用原工作项，确定原因、当前范围、边界、输入、完成条件和真实未决问题。行为细节引用 Spec，不复制成第二份长期规格。
6. 协调方案区分依赖阻塞开始、集成、验收还是发布；识别共享修改与可并行前沿，明确交接和统一候选责任。
7. 执行协调在授权内使用宿主委派或串行推进，核对实际 diff/构件/命令；只调整受变化影响的工作，将结果整合到同一候选并完成必要受影响验证。
8. 无新增事实或必要动作时允许零写入；合适的既有 Issue 可承载 Deferred，不为每个细节另建工作。

## 输出与完成条件

规划输出目标覆盖、具体交付组成、阶段结果、近期可接手工作、依赖与未知。单项输出限定工作及完成条件。方案协调输出串并行与交接安排；执行协调输出统一候选、真实修改、验证和剩余限制。规划可用不等于产品已交付。

## 停止与例外

产品优先级和未确认取舍由用户决定，授权范围内无需反复请求相同许可。工具不足只阻塞对应动作；兄弟 Skill 未安装不能让已获准执行协调退化为只给计划。无关未知不阻塞当前可做部分。

## 示例

一个共享字段要改名：不是为数据库、服务、API 分别建互相无法集成的任务，而是先引入可兼容新形式，再按调用范围迁移，最后删除旧形式并验证统一候选。用户只问拆法时止于方案；已授权执行时完成实际交接与集成。
