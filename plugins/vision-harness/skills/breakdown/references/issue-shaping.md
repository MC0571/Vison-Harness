# 单项工作整理

直接读取一个既有 Issue 或用户给定工作，不要求重新解释完整产品历史。

整理顺序：

1. 原因：它解决哪个已确认问题，引用现有目标而不复制全文。
2. 当前范围：本轮必须产生的可观察结果。
3. 边界：Deferred、Non-goal、不会自动获得的后续权限。
4. 输入：准确候选、依赖结果、相关 Spec/接口和环境。
5. 完成条件：能判断满足/违反的结果与最低必要证据。
6. 未决问题：只保留会改变范围或方案且当前无法查明的事项。

优先修订原工作项；只建议时不写。不要因标题不理想复制新 Issue，也不要把实现步骤写成长期行为 Spec。

例：缺陷 Issue 已含复现和范围，只补“修复后不得改变兼容接口”与回归入口，不升级为全景路线图。
