# 全景产品规划

## 建立映射

从已确认目标出发，依次回答：使用者获得什么阶段结果；哪些真实组件、入口或材料共同提供它；主要工作由哪个已有或必要工作项承载；用什么证据判断阶段结果。组件必须可辨认，不能只有“治理能力”“质量能力”等抽象名词。

近期工作细化到下一位执行者能找到输入、边界和完成条件；远期已确认能力保持粗粒度承载，不提前拆到文件和函数。候选实现保持候选身份，不自动变成需求。

## 动态事实

GitHub 承载工作、依赖和进度；Spec 承载长期行为；架构承载当前长期结构；重大已作决定才进入 ADR。不要建立平行 ROADMAP/tasks 数据库。Deferred 使用已有合适工作项承载即可，Non-goal 则表示明确不做。

例：阶段结果“单 Skill 可独立复制”应映射到完整 Skill 目录、导出命令、完整性校验和迁移证据，而不是只列“改进打包”。

## 结束

当主要目标有具体承担、近期批次可接手、依赖和证据足以继续时停止。长期目标未完成不阻塞当前合格阶段；当前切片也不能冒充长期完成。
