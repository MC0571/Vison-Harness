# Pull Request 审查

1. 固定 PR URL/编号、当前 head、base 和比较范围，检查是否有并发更新。
2. 读取原始 PR 描述、diff、关联约定和检查结果；作者摘要只作导航。
3. 核对范围是否匹配请求，有无意外文件、生成物漂移或秘密信息。
4. 判断已有 Spec/Code 审查及证据是否覆盖当前 head；只补变化影响部分。
5. 检查目标分支、冲突、合并要求和事项关闭语义。若需合并后验证，自动关闭关键词是风险。
6. 分开给技术判断、证据限制和实际合并授权；审查通过不执行合并。

异常：head 在审查中变化。记录新旧 SHA，只重读受影响 diff 和证据；无法固定时暂停总体批准。
