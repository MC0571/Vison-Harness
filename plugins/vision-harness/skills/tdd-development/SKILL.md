# TDD Development

交付授权范围内的实现与基本验证，或在只授权诊断时交付可证据支持的原因与边界。

## 何时使用／何时不使用

用于新增行为、修复缺陷、受行为保护的重构或只读诊断。不用于只审查候选或只运行既定验收；只调查时不得顺手修复。

## 输入与环境条件

需要当前承诺、允许修改范围、候选和停止位置。命令必须来自项目现有配置；语义歧义或产品取舍由用户决定。缺测试入口不授权引入新框架，但不阻止已授权定位与最小实现判断。

## 开始前的最少读取

读取适用规则、请求/Issue、相关 Spec、目标实现及所有直接调用者；检查工作区和候选。缺陷先沿调用路径定位共享根因，避免只补报告路径的症状。

## 执行步骤与关键分支

1. 固定授权范围、候选和可观察承诺。
2. 从 manifest、脚本、Makefile、CI 等找到真实测试入口，选与目标行为对应的最小命令；先区分目标失败、已有无关失败和环境失败。
3. 建立失败依据：新增行为写最小失败检查；已有稳定失败测试可复用；缺陷复现后追踪最早偏离；纯重构先确认现有保护。
4. 选择一个可观察切片，实施最小根因修复；不按数据库→服务→API堆层后最后补测试。
5. 重跑同一目标测试，确认由目标红灯变绿；再按受影响接口、调用者和持久化扩大回归。
6. 只有测试保护成立后重构，并用复杂度判据删除推测性抽象而保留安全、数据完整性和可信故障保护。
7. 记录实际命令、结果、修改文件、候选和未验证范围；没有合并/发布授权即停止。

## 输出与完成条件

输出完成行为或诊断结论、修改文件、实际命令与结果、剩余失败/未验证范围及候选标识。实现必须完成当前修改所需基本验证；只读诊断以可复现证据和未证实范围结束；环境阻塞不能写成通过。

## 异常与停止边界

红灯若来自拼写、夹具或环境先修正测试设置，不借机削弱断言。不可复现时不宣布根因；连续尝试无信息增益时重新检查假设。未经授权不提交、推送、开 PR、合并或发布。

## 简短输入输出示例

正常：复现共享解析函数对编码路径的越界错误，在共享函数加入根因检查，目标测试转绿并运行所有调用者回归。

边界：只授权诊断且故障不可复现，输出已尝试条件、观察和下一判别检查，不修改代码。
