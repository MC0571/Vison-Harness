# 行为切片的红—绿—重构

## 循环外先固定承诺

辨认本轮必须完成的行为、现有契约与关键风险。可以用当前工作上下文保存轻量检查项，不新增长期任务状态文件。循环中发现真歧义时只暂停受影响部分，不把实现方便当成缩小范围的理由。

## 新增行为

1. 选择一个能观察结果的稳定入口，以及当前最有判别力的行为切片。
2. 从确认规格、独立例子或不变量得到期望，写最小检查并运行。
3. 红灯应来自缺少或违反目标行为，而非夹具、拼写或环境。测试直接通过时确认是否已经实现或测试没有判别力，不能无故破坏代码造失败。
4. 写足以满足该行为的最小正确实现，不迎合某个样例硬编码，也不预建无关未来能力。
5. 重跑同一检查确认变绿；再根据剩余承诺取下一片，而不是先写整批假定结构的测试再一次性实现。

## 可复现缺陷

现有失败测试精确覆盖原症状时复用。否则先得到可判别复现，再转为正确边界上的回归检查。定位共同根因，检查受影响真实调用者；不要只修报告路径的表面症状。

修复后同时运行缩小后的回归与原始场景，避免把复现缩成了另一种问题。

## 纯重构

先确认现有行为保护；保护不足时补能捕捉预期破坏的检查，不强求先有业务红灯。重构不改变承诺，完成后重跑同一检查和受影响回归。

若测试仅因私有命名或内部调用顺序变化而失败，先辨认它是否错误耦合实现；不能直接削弱真正的行为保证，也不能为保留坏测试冻结内部结构。

## 绿灯后的整理

在保护成立时改善命名、职责与重复，保持小步可回退。重构可以属于循环，但不是每轮必做，也不是把全仓清理纳入本轮的许可。

## 收口

核对当前全部承诺、跨切片交互、错误与必要回归。通过数量不等于语义覆盖；但未触及的远期需求也不阻塞本轮完成。命令与结果绑定准确候选，未执行部分明确保留。
