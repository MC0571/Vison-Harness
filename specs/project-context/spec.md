# 项目接入、任务接续与指引的共享行为约定

## 适用职责

本文件按项目上下文这一语义边界组织，不规定一个同名 Skill。组件划分见 [产品架构](../../ARCHITECTURE.md)。

| 工作 | 应返回的结果 | 不代替的责任 |
| --- | --- | --- |
| using-vision-harness | 本轮任务、必要事实、有效权限、下一步与适用入口 | 不代替规划、实施或接受，不要求所有调用经过入口 |
| project-onboarding | 采用方法所缺的条件，以及获准的最少接入变更 | 不重做已有合格愿景、规划和规则 |
| agent-instructions | 全仓/局部 Agent 指引，以及按需的项目审查规则与宿主执行入口 | 不复制 Spec/架构，不冒充实际审查结果，也不放宽当前审查标准 |

上述职责可在一个任务中协作，但结果和副作用边界分别成立。通用规则引用 [METHOD.md](../../METHOD.md)，愿景与规划分别引用 [Vision](../vision/spec.md) 和 [Breakdown](../breakdown/spec.md)。每个直接调用的工作都核对自身条件，不能假定入口已经检查过。

## 来源与上下文正确性

必须辨认目标项目、工作目录、当前请求和相关来源。方法包的规则是操作依据，不是消费项目的产品愿景；包内示例或其他项目材料不自动成为本项目事实。

复用已有组织级愿景、目录、规则和工作入口。名称与默认模板不同不是重建理由。上下文读取以当前决定需要为限；跨范围影响或真实冲突出现才扩大，不每次扫描全部历史。

承诺、状态、提案、有效决定、证据和授权不可互相替代。冲突先核对对象、版本、范围和时间；旧事件可以继续作为历史证据。未解决冲突只阻塞依赖它的决定，不阻止无关的只读工作。

返回截断、缺少来源或不可访问时，必须说明已知与缺失及其影响，不能猜测完整内容或从摘要推导新权限。存在完整读取办法时应使用；无法安全写入时只暂停对应写入。

## 新会话与授权有效性

新会话应从可读取的持久项目事实恢复，不依赖旧 transcript、隐藏记忆或已失效临时路径。交接摘要只能引导定位，关键来源仍须核对。

持续委托在仍适用于当前对象与动作时可以复用，不因换会话机械重问。已撤销、过期或范围改变的授权不得继承；工具可写、CI 通过、审查通过、合并或 Issue 关闭都不创造许可。存在多个相互冲突的授权线索时只暂停相关副作用，不能任意选取对执行最方便的说法。

必要事实与权限足够时应指出或执行获准下一步，不重新访谈或规划；无需新产物可以是成功结果。接续不产生私有状态文件、重复工作或无意义指引更新。

## 按缺口接入与规则维护

接入既有项目时，应区分缺失入口、规则冲突与无需修改。愿景、规划、指引、审查配置各已足够时，不再强制逐项调用。新项目缺少愿景可以进入获准讨论，不自动创建模板套餐或实施树。

指引写入只在本轮确需且已授权时发生。根目录保存全仓约定，局部文件保存局部差异；已有权威规则应引用。构建与测试命令须有真实来源，不能猜测。修改局部文件须保留原有安全与审查要求，不能为当前任务方便降低标准。

文件存在、手动读取和宿主自动加载是三种不同事实。加载方式依实际宿主核验，不能静默改全局配置、信任级别或权限。审查配置由 agent-instructions 的审查配置模式维护并引用项目规则，不能另存一套竞争标准；配置完成不等于某个候选已通过审查。

## 条件交接与分发隔离

交接应能辨认任务范围、来源/版本、允许副作用、缺口和期望结果，优先引用现有对象，不要求专门交接文档。接收方只核对与自身动作有关的前提，不重复上游全部工作。

愿景整理不自动写规划，规划建议不自动变成已批准实施。任何环节不足应准确报告，前项完成不能抵消后项缺失。上下文恢复可在不同工作位置发生，不强制“接入→愿景→规划”的通用流水线。

运行规则来自当前 Skill 根目录内的必要资源，消费项目事实来自其权威来源。普通 Skill 必须能连同本地 references/assets 单独复制使用，不得依赖提供者仓库的 METHOD/Spec/Eval、兄弟 Skill 或 Plugin 根级方法文件。运行资源缺失不得用旧源码或其他版本静默替代；无关项目定位可以继续。安装更新不得覆盖项目愿景、指引、自定义规则和既有工作。

## 验证

按责任验证入口接续、项目接入、指引维护和审查配置，而不要求它们始终同时执行。应覆盖组织级入口、无须修改、授权持续/撤销、局部规则、安全写入、事实冲突、读取截断、直接调用和新会话。

新会话只收到当轮请求与持久项目事实，不注入旧对话或隐藏摘要。共享约定的场景可以覆盖多个 Skill，不为每个入口复制一份相同判据。结构、加载、单入口行为和组合结果分别报告；具体设计见 [项目启动验证说明](../../evals/project-startup/README.md)。
