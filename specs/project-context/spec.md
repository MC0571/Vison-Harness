# Project Context 行为规格

## 用途与职责

Project Context 帮助 Agent 接入新旧项目、找到当前适用事实与规则、恢复本轮任务和有效授权，并按需要维护项目工作约定。它不维护自己的项目状态数据库，不替代 GitHub，也不接管所有工作的调度。

通用判断见 [METHOD.md](../../METHOD.md) 与 [架构边界](../../ARCHITECTURE.md)。愿景行为由 [Vision](../vision/spec.md) 定义，规划行为由 [Breakdown](../breakdown/spec.md) 定义。上下文准备可以发生在愿景澄清之前、规划之后或具体任务开始时，不要求固定的 Skill 调用流水线。

## 定位并读取足够的事实

先确认目标项目、工作目录、本轮意图和允许的副作用。区分 Plugin 自身的规则/规格与消费项目的目标/约束；不能因 Plugin 包内也有 VISION.md 就把它当成消费项目愿景。

复用项目既有的愿景、Spec、架构、工作入口与组织级来源；路径名和目录布局不同不构成重新初始化的理由。只读取支撑当前决定的相关上下文；跨范围影响或真正冲突出现后再扩大读取，不每次扫描全部历史。

承诺、原生状态、提案、有效决定、证据和授权分别理解。描述不一致先核对对象、版本、范围和时间；旧的真实事件不因新事实出现而变成错误记录。无法解决的冲突只阻塞受影响动作，允许不受影响的只读调查或准备继续。

入口不可访问、返回被截断或缺少来源时，明确读到了什么、缺什么以及影响。可以给出有限判断，不能假称恢复完成、猜测缺失授权，或用摘要覆盖完整事实。

## 新会话恢复与权限

新会话不依赖旧聊天、隐藏记忆或临时路径。从现存的项目记录恢复当前目标、相关工作、决定、证据与下一步。收到交接摘要时回读其关键来源；摘要不是新的权威状态。

授权必须仍适用于当前对象和动作。已有明确项目委托可以持续有效，不因换会话就机械重问；旧记录只授权某次讨论、范围已经变化或授权已撤销时，不能继续外推。CI、审查通过、合并或 Issue 关闭本身不产生后续实施/发布权限。

若只缺少当前决定所需的定位或授权信息，指出最少必要问题。相关目标、约束、依赖与授权已经足够时，直接指出或执行获准的下一步，不重新生成全局规划，不强制用户重复已知背景。

无新事实且已有上下文足够时，允许无需改动的结果。重复接入不产生重复 Issue、无意义规则文件或进度缓存。

## 维护适用的 AGENTS.md 与规则入口

只有任务需要且已获相应写入授权时，才创建或修改项目规则。根目录承载全仓适用约定，局部文件只承载局部差异；无差异不新建，有权威规则可引用时不复制整套正文。

保留项目原有的构建命令、安全边界和审查要求；从实际配置验证命令来源，不编造可执行入口。修订失效或冲突规则时指出依据与影响，不能为当前任务通过检查而自行放宽标准。

规则读取遵循实际宿主的适用范围和覆盖方式。文件存在、Agent 手动读过、宿主自动加载三者分别报告；不能把手动阅读当作加载机制已经生效，也不能静默修改用户全局配置、信任级别或权限。

规则写入遵循 METHOD 的完整读取、保留无关内容、并发检查与写后核验原则。无法安全更新时只暂停相应写入，不重复初始化项目。

## 与 Vision、Breakdown 的交接

交接使用已有权威记录及引用，而不是新增三份独立的状态文件：

| 交接内容 | 应由什么承载 |
| --- | --- |
| 当前项目身份与目标 | 项目入口、权威愿景及其适用版本/读取依据 |
| 已确认目标和未决问题 | 愿景及有关的有效决定；建议稿保持建议身份 |
| 具体交付、依赖和下一批 | GitHub 当前工作、原生关系与相关方案，不复制另一份任务状态 |
| 允许继续的范围 | 用户本轮要求或仍适用的明确委托，不从工作状态推导 |
| 已验证与未验证内容 | 对应候选的实际证据和缺口，不以文件存在代替 |

Vision 只写完愿景时，不自动调用 Breakdown 写规划；Breakdown 的建议未接受时，新会话不把它当成正式任务。交接不扩大权限。任何必要环节尚不可用时说明影响，不用成功的单组件结果证明整条路径成立。

安装或更新 Plugin 不得覆盖消费项目的特有规则、愿景与规划。随包引用缺失时不静默从旧源码目录或其他版本取材料冒充当前包正确；对可独立进行的事实读取可继续，并明确方法材料缺口。

## 结束与验证

输出应使接手者辨认当前项目、适用来源、本轮权限、已有进展的证据范围、真正阻塞项、下一步和停止边界。格式按任务需要，不要求每次生成相同上下文报告。

验证需包含既有目录、组织级愿景、无旧聊天的新会话、持续委托与已撤销授权、冲突与截断、局部规则维护、重复执行、错误包引用及组合交接。新会话测试仅提供当轮请求和可读取的持久项目事实，不能塞入先前隐藏对话。

安装成功、规则加载、单 Skill 行为与完整用户路径分别判断；材料设计或准备检查完成不等于产品交付。具体案例见 [项目启动验证说明](../../evals/project-startup/README.md)。
